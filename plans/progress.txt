## tree-view (done, 2026-11-11)

- Ark 6 / Zag 2 rewrote the tree view anatomy: no more `Branch`, `BranchControl`, `BranchContent`, `Item`,
  `ItemText`, `BranchIndentGuide`. It's `Node` (the row, branch or leaf), `NodeGroup` (a Collapsible root wrapping a
  branch row and its children), `NodeGroupContent`, `NodeExpandTrigger`, `NodeIndicator` (with a required
  `type: expanded | selected | checked | indeterminate`), `NodeText`, `IndentGuide` and `Cell` (a gridcell; the tree is
  now `role="treegrid"`). Chakra is still on Ark 5, so its API couldn't be copied as-is.
- Recipe: slots renamed to the Ark 6 anatomy. `branchControl` and `item` were identical and became one `node` slot;
  `branchIndicator`/`itemIndicator` became `nodeIndicator` (rotates 90deg on `_open`, which only the `expanded` type
  sets; `_hidden` hides the other types since `display: inline-flex` beat the `hidden` attribute). Added `cell` and a
  bordered `nodeRenameInput`. Solid variant forces the indicator to `currentColor` on selected rows. Breaking for anyone
  using the old slot names, so the panda-ds changeset is `minor` (0.x). No analog override exists.
- Components: Chakra's recursive `TreeView.Node` helper is `TreeView.Nodes` here, because Ark 6 took `Node` for the
  row. It takes `render`, `indentGuide`, `nodeGroupProps`, `nodeGroupContentProps`. Per framework:
  React `render` prop + `indentGuide` element; Vue scoped default slot `{ node, indexPath, nodeState }` + `#indentGuide`
  slot; Svelte `render` snippet + `indentGuide` snippet; Solid `render` gets `nodeState` as an accessor (Ark Solid's
  node context is an accessor, and a plain object would go stale) and `indentGuide` is a function, since one Solid JSX
  element can't be mounted in several groups.
- `NodeIndicator` defaults `type` to `expanded` and renders `chevron-right` when it has no children (the PRD's "branch
  indicator defaults to a chevron"); other types have no default child.
- Vue `NodeRenameInput` needed the listbox `Input` cast (`FunctionalComponent<HTMLArkProps<"input">>`), otherwise TS2590.
  `ContextProps` is generic over `TreeNode` in React, Vue and Solid.
- Demos (10): usage, sizes, variants, default-expanded, controlled-expansion, multi-select, checkbox (a `Checkmark`
  inside `NodeCheckbox`), disabled-node, expand-collapse-all (via `TreeView.Context`), collapse-animation
  (`animateContent`). Skipped Chakra's async, context-menu, custom-icon, explorer, filter, links, mutation, lazy-mount,
  store and remove-indentation. The collection is declared at the bottom of each demo; `Nodes` does the iteration, so no
  `.map` in the demos. Leaf rows have no spacer, so a leaf's icon sits under its sibling branch's chevron (Chakra's
  basic demo looks the same).
- Story/docs titles are sentence case ("Tree view"), like "Scroll area".
- Storybook check (all four): 6 rows → 9 after opening node_modules, chevron rotates to 90deg, one indent guide, row
  padding 12px → 36px one level down, ArrowDown moves focus, solid vs subtle selected bg differ, controlled expansion
  toggles, checking `src` checks its children, expand all opens 3 branches and collapse all closes them, disabled node
  has `data-disabled`, sizes pad 4/4/6px.
- Note for next: cold `tsc` for solid (compositions and storybook-solid) and `svelte-check` in compositions take 20 to
  60 minutes when they run alongside each other; it's not the new code (an incremental recheck of the solid demos takes
  2s). Run typechecks one at a time in the background. `timeout` isn't installed on this Mac.

## json-tree-view (done, 2026-11-15)

- New slot recipe `json-tree-view` with slots root and tree only. Ark exports just Root, RootProvider and Tree;
  Node, KeyNode and ValueNode are internal components that `Tree` renders itself, so they can't be wrapped. The tree
  slot styles them by descendant selectors on the markup they produce: Ark's tree-view parts
  (`[data-tree-view-node]`, `-cell`, `-node-indicator`, `-node-text`, `-indent-guide`, `-node-group(-content)`) and
  json-tree-utils' `data-kind` (key, colon, brace, preview-text, constructor, operator) and `data-type` (string,
  number, boolean, null...). Designed from Ark's `json-tree-view.module.css`, whose `branch-*`/`item` part names are
  out of date for v6. Chakra and tl-ds have none.
- Syntax colours are palette `*.fg` tokens: key `purple.fg`, string `green.fg`, number/bigint/date `blue.fg`,
  boolean/function `orange.fg`, regex/symbol `pink.fg`, constructor `teal.fg`, colon `fg.muted`, error `fg.error`,
  null/undefined/preview text `fg.muted` italic. The `code.*` tokens the Panda MCP lists exist only in
  `apps/www/theme`, not in panda-ds, so they compile to nothing in the recipe.
- `--tree-depth`/`--tree-offset` must be declared on the row and the indent guide, not on the tree: Zag sets
  `--depth` per node, and a custom property declared where `--depth` is undefined goes invalid (padding came out 0).
  Leaves add one icon + gap of padding so their text lines up with branch text. `[data-type=...]` doesn't clash
  with the indicator's `data-type="expanded"`.
- Variants plain (default), outline, subtle (padded box with border or `bg.subtle`, like timer). Sizes sm/md/lg:
  textStyle xs/sm/md, icon 12/16/16px, row padding 1/1.5/2. Mono font, `lineHeight: taller`. No analog override.
- `Tree` defaults `arrow` to a `chevron-right` Icon in all four. Two Ark bugs worked around in the wrappers:
  Solid's `Tree` copies props into a plain object, so a JSX `arrow` is one DOM node that ends up only in the last
  row; the wrapper passes a function (cast to `JSX.Element`) so each row renders its own icon. Vue's `Tree` always
  forwards an `indentGuide` slot, so the node never falls back to the boolean prop; the wrapper declares
  `indentGuide: Boolean` and supplies a slot that renders Ark's `TreeView.IndentGuide`. Also Ark's
  `typeof indentGuide === "boolean"` means `indentGuide={false}` still draws guides (React, Svelte); not patched.
- Svelte root has `bind:expandedValue/selectedValue/focusedValue/checkedValue` and no `ref` (Ark's json-tree-view

## frame (done, 2026-11-15)

- New plain recipe `frame` (not a slot recipe): `display: block`, `width: full`, 1px `border`, `l2` radius and
  `height: [calc(var(--height) + 2px)]` (the global border-box sizing puts the two border pixels inside the height,
  so plain `var(--height)` clipped the content by 2px; `content-box` instead would overflow `width: full`). Ark's Frame keeps `--width`/`--height` on the iframe in sync with the mount node's scroll
  size through a ResizeObserver, so the frame grows to its content without every demo setting Ark's inline
  `height: var(--height)`. No background: when the page's color scheme differs from the frame document's, the browser
  paints the iframe canvas opaque anyway. No variants, no analog override.
- The PRD lists parts Frame and Content, but Ark exports only `Frame`; `FrameContent` is an internal wrapper that fires
  `onMount`/`onUnmount`, so there is no Content part to wrap or style. Ark's API differs per framework and the wrappers
  keep it: React/Solid `head` is an element, Vue `#head` slot and `@mount`/`@unmount` emits, Svelte `head` snippet and
  `bind:ref`; the custom document is `srcDoc` in React and Vue and `srcdoc` in Svelte and Solid.
- Components: React, Vue and Solid are `styled(ArkFrame, frame)` (single element, so no namespace.ts, like `image`).
  Svelte is a port of Ark's `frame.svelte` (+ its internal `frame-content.svelte`) with `unstyled` and class, not a
  wrapper: Ark's Svelte Frame derives `mountNode` from the iframe before its effect runs `doc.write()`, so the
  children portal into the `about:blank` body that the write then replaces, and the frame stayed empty with
  `--height: 0px` (head content survived because it's read later). The port keeps `mountNode` in `$state` and sets
  it after the write, as Ark's React version does. Drop the port once Ark fixes it.
- Ark measures the mount node (`.frame-root`, or `body` with a custom `srcDoc`), so padding on `body` around
  `.frame-root` gets cut off; the demos pad `.frame-root` and the docs say so.
- Demos (4, Ark's): usage (= basic), inherit-styles, script, src-doc. Panda's classes don't reach the iframe, so the
  usage and script demos style their content with a `<style>` in `head` (Vue builds it with `h("style")`, since a
  `<style>` tag in a Vue template is dropped; Svelte uses `{@html}` in the `head` snippet). inherit-styles copies the
  page's `<style>` and stylesheet `<link>`s into the frame in `onMount` and then uses our `Heading` and `Text` inside
  it. script appends a `<script>` that writes into a paragraph instead of Ark's `console.log`, so the effect is
  visible. src-doc loads Open Sans from Google Fonts (Ark also loads Font Awesome; dropped). Vue reaches the iframe
  through a wrapper `div` ref because the styled component's template ref is a component instance.
- Docs category `Layout`.
- `ds-api.json`: `api:generate` again reordered `typeahead` in the listbox and tree-view entries; those hunks were
  dropped so the diff is only the `frame` key.
- `apps/storybook-svelte` runs with `exactOptionalPropertyTypes`, which `packages/ui/svelte` doesn't, so the ported
  Svelte props need `| undefined`; only the storybook typecheck caught it.
