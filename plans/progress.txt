## skip-nav (done, 2026-11-10)

- Recipe: added `zIndex: "skipNav"` to the focus-visible state (tl-ds has a skipNav z-index; the token already existed
  in panda-ds but the recipe didn't use it). No analog override exists.
- Components: `SkipNavLink` and `SkipNavContent` as two flat exports, no `namespace.ts` (same shape as
  `link-overlay`; there's no root/parts). `id` on `SkipNavLink` is the target id, not the link's own id (Chakra/tl-ds
  API); it becomes `href="#<id>"`. Default id is `skip-nav` (Chakra uses `chakra-skip-nav`).
- `SkipNavContent` is `tabIndex=-1`, `outline: "[0]"`. `outline: "0"` fails strictTokens in compositions (no zero
  border token), so it uses the escape hatch.
- Vue `SkipNavLink` is a `defineComponent` wrapper reading `attrs.id`; Svelte link isn't generic over the tag (always
  `a`).
- Only a `usage` demo: Chakra has no other skip-nav examples. Docs have no `<RecipeVariants />` (no variants).
- Storybook check (all four): link clipped until Tab, then fixed at top/start 6 with z-index 1600; Enter moves focus
  to `#skip-nav`.
- Note for next: none of the touched packages have a `test` script, so `pnpm test` is a no-op here.


## scroll-area (done, 2026-11-10)

- Recipe: kept the existing Chakra-shaped API (`variant: hover | always`, sizes `xs`–`lg`) and look (gray
  `colorPalette.solid/10` track, `/25` thumb). Ported tl-ds's `shadowOverflow` boolean variant (mask fade on the edges
  not at the scroll start/end, vertical-only or horizontal-only overflow). Default is `false`, not tl-ds's `true`, so
  existing scroll areas don't change. Gradient rewritten with `black`/`transparent` (no hex) and without tl-ds's
  `@property` registrations, which only matter for transitions. tl-ds's `showScrollbar` was skipped: it duplicates
  `variant="always"`. Same variant added to the analog override (which had no `description`; left as is).
- Components: `ScrollArea.Scrollbar` defaults its children to `ScrollArea.Thumb` (tl-ds). Svelte has no bindables
  beyond `ref`. Exports the zag `ScrollToDetails`/`ScrollToEdge`/`ScrollToEdgeDetails` types.
- Demos: usage, horizontal, both-directions, sizes, variants, scroll-shadow (uses `shadowOverflow` instead of Chakra's
  inline mask CSS), thumb-styling, scroll-to-edge (Chakra's "scroll to side"), scroll-to-position. Skipped Chakra's
  virtualization, stick-to-bottom (extra deps), with-menu, rtl and with-store (same as scroll-to-*). Lorem text and
  boxes are written inline; heights use size tokens (`36` for Chakra's 8.5rem, `2xl` for 40rem).
- Storybook check (all four): scrollbar hidden until hover with `hover`, visible with `always`; sizes 4/6/8/12px;
  shadow mask switches from 0px to 4rem at the top after scrolling; scrollToEdge and scrollTo work.
- `ds-api.json`: the generator drops `defaultValue` for boolean variants, so `shadowOverflow` shows no default.


## carousel (done, 2026-11-11)

- Zag 2 renamed the root props: it's `count` (not Chakra's `slideCount`) and `autoPlay` (not `autoplay`). Demos and docs
  use the Zag 2 names.
- `page` collides with the CSS `page` style prop, so Panda swallowed it and typed it as a style value. `CarouselRoot`
  uses `forwardProps: ["page"]` in React, Vue and Solid (Chakra does the same). `RootProvider` has no `page` prop and
  doesn't forward it. Watch for this on any Ark root whose prop shares a name with a CSS property.
- Recipe: Chakra's look (tl-ds has no carousel). Removed the duplicate `progressText` slot, added `progressText` styles
  (`sm`, tabular nums, `fg.muted`), and `_vertical` triggers rotate their icon 90deg, so the default chevron points
  up/down in vertical carousels without the component reading orientation. No analog override exists.
- Components: `PrevTrigger`/`NextTrigger` with no children render `asChild` into a ghost `xs` `IconButton` with
  `chevron-left`/`chevron-right` (the floating-panel stage trigger pattern). Added Chakra's `Carousel.Indicators`
  helper (one indicator per `pageSnapPoints` entry, forwards its props to every indicator). `ProgressText` and
  `AutoplayIndicator` are Ark's as-is (Ark's indicator takes `children` while playing and `fallback` while paused,
  instead of Chakra's `play`/`paused` props).
- Demos (13): usage, with-indicators, vertical, spacing, slides-per-page, slides-per-move, with-mouse-drag,
  with-autoplay, controlled, with-progress-text, with-floating-arrow (custom outline triggers via `asChild`),
  variable-size, with-thumbnails. Skipped Chakra's with-images (needs a local ActionButton helper), composition (big
  static property list), with-dialog and with-store. Slides are inline `Center`s; `spacing` uses rem strings (`3rem`,
  `2rem`, `0.5rem`) since it's a Zag prop, not a style prop. Thumbnails' current outline uses `[2px]` escape hatches
  (no outline-width token); images are Unsplash, like the aspect-ratio demo.
- Docs have no `<RecipeVariants />` (the recipe has no variants).
- Note for next: `pnpm generate` in `apps/www` takes over 10 minutes here (it builds compositions); run it in the
  background. Storybook pages never reach `networkidle` (HMR socket), so wait on `load` plus a selector in Playwright.
- Storybook check (all four): 5 indicators, default prev/next render an `xs` icon button with an svg, next moves the
  current indicator 0 → 1, vertical trigger icons are rotated 90deg, controlled `page` updates (Vue needs ~1.5s after
  the click before `data-current` moves), progress text reads `1 / 5`. Vue logs `injection "Symbol(PropsContext)" not
  found` for the default icon buttons; it's pre-existing (the plain `DS/Button` story logs it too) and comes from
  Panda's generated `create-recipe-context.js` injecting without a default.


## tree-view (done, 2026-11-11)

- Ark 6 / Zag 2 rewrote the tree view anatomy: no more `Branch`, `BranchControl`, `BranchContent`, `Item`,
  `ItemText`, `BranchIndentGuide`. It's `Node` (the row, branch or leaf), `NodeGroup` (a Collapsible root wrapping a
  branch row and its children), `NodeGroupContent`, `NodeExpandTrigger`, `NodeIndicator` (with a required
  `type: expanded | selected | checked | indeterminate`), `NodeText`, `IndentGuide` and `Cell` (a gridcell; the tree is
  now `role="treegrid"`). Chakra is still on Ark 5, so its API couldn't be copied as-is.
- Recipe: slots renamed to the Ark 6 anatomy. `branchControl` and `item` were identical and became one `node` slot;
  `branchIndicator`/`itemIndicator` became `nodeIndicator` (rotates 90deg on `_open`, which only the `expanded` type
  sets; `_hidden` hides the other types since `display: inline-flex` beat the `hidden` attribute). Added `cell` and a
  bordered `nodeRenameInput`. Solid variant forces the indicator to `currentColor` on selected rows. Breaking for anyone
  using the old slot names, so the panda-ds changeset is `minor` (0.x). No analog override exists.
- Components: Chakra's recursive `TreeView.Node` helper is `TreeView.Nodes` here, because Ark 6 took `Node` for the
  row. It takes `render`, `indentGuide`, `nodeGroupProps`, `nodeGroupContentProps`. Per framework:
  React `render` prop + `indentGuide` element; Vue scoped default slot `{ node, indexPath, nodeState }` + `#indentGuide`
  slot; Svelte `render` snippet + `indentGuide` snippet; Solid `render` gets `nodeState` as an accessor (Ark Solid's
  node context is an accessor, and a plain object would go stale) and `indentGuide` is a function, since one Solid JSX
  element can't be mounted in several groups.
- `NodeIndicator` defaults `type` to `expanded` and renders `chevron-right` when it has no children (the PRD's "branch
  indicator defaults to a chevron"); other types have no default child.
- Vue `NodeRenameInput` needed the listbox `Input` cast (`FunctionalComponent<HTMLArkProps<"input">>`), otherwise TS2590.
  `ContextProps` is generic over `TreeNode` in React, Vue and Solid.
- Demos (10): usage, sizes, variants, default-expanded, controlled-expansion, multi-select, checkbox (a `Checkmark`
  inside `NodeCheckbox`), disabled-node, expand-collapse-all (via `TreeView.Context`), collapse-animation
  (`animateContent`). Skipped Chakra's async, context-menu, custom-icon, explorer, filter, links, mutation, lazy-mount,
  store and remove-indentation. The collection is declared at the bottom of each demo; `Nodes` does the iteration, so no
  `.map` in the demos. Leaf rows have no spacer, so a leaf's icon sits under its sibling branch's chevron (Chakra's
  basic demo looks the same).
- Story/docs titles are sentence case ("Tree view"), like "Scroll area".
- Storybook check (all four): 6 rows → 9 after opening node_modules, chevron rotates to 90deg, one indent guide, row
  padding 12px → 36px one level down, ArrowDown moves focus, solid vs subtle selected bg differ, controlled expansion
  toggles, checking `src` checks its children, expand all opens 3 branches and collapse all closes them, disabled node
  has `data-disabled`, sizes pad 4/4/6px.
- Note for next: cold `tsc` for solid (compositions and storybook-solid) and `svelte-check` in compositions take 20 to
  60 minutes when they run alongside each other; it's not the new code (an incremental recheck of the solid demos takes
  2s). Run typechecks one at a time in the background. `timeout` isn't installed on this Mac.
