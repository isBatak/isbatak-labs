Items keep their own height and stack into columns without gaps, like a Pinterest board. Modeled on
[MUI's Masonry](https://mui.com/material-ui/react-masonry/), and works in React, Vue, Svelte, Solid, Preact and vanilla
JS.

- Each item goes to the shortest column, or fills the columns in order
- A fixed column count, a minimum column width, or a column count set from CSS per breakpoint
- Items can span several columns
- Re-lays out when an item resizes, an image loads, or items are added or removed
- Renders as a plain grid until measured, so server-rendered markup reads fine before hydration
- RTL support

## Examples

Scroll to an example to load it in the preview, and open the code view there for the full source. The settings button in
the preview changes the example live, and the snippet under it follows. Each example is its own registry item, so you
can add it with the CLI the same way.

Items must be direct children of the root, and each one needs a unique `value`.

### Image masonry

<Example id="masonry-image" settings={{ columns: 3 }}>

Items can hold anything, images included. The layout runs again as each image loads, so lazy-loaded images don't need a
known size up front. Items are placed in reading order, row by row.

</Example>

### Items with variable height

<Example id="masonry-variable-height" settings={{ columns: 3 }}>

Every item is watched for size changes. Open an accordion and the items below it move, and may switch columns, so each
one still lands in the shortest column.

</Example>

### Columns

<Example id="masonry-columns">

Set `columns` for a fixed count. To change it per breakpoint, leave `columns` unset and set the `--masonry-columns` CSS
variable on the root instead, here 3 columns on small screens and 4 from `sm` up. Set `minColumnWidth`, for example
`"12rem"`, to fit as many columns as there is room for.

</Example>

### Spacing

<Example id="masonry-spacing" settings={{ columns: 3 }}>

Set `gap` to a number of pixels or a CSS length. Leave it unset to take the spacing from CSS, so it can change per
breakpoint, here from `2` to `6`. With Panda CSS, the recipe's `gap` variant picks from the spacing tokens.

</Example>

### Sequential

<Example id="masonry-sequential" settings={{ columns: 4, sequential: true }}>

Set `sequential` to fill the columns in order, left to right, instead of adding each item to the shortest column.

</Example>

### Spanning columns

<Example id="masonry-span" settings={{ columns: 3 }}>

Set `span` on an item to make it cover several columns. It goes where the columns it covers are shortest, and the span
is capped at the number of columns.

</Example>

## Server-side rendering

Until the items are measured, the root is a plain CSS grid with the same columns and gap, so server-rendered markup
shows every item in place without overlapping. After hydration the items are measured and moved into their columns, and
the root gets a `data-measured` attribute. There's no need for a default height or column count.
